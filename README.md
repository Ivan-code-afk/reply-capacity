# Reply Capacity — рабочий MVP одной функции

**Задача:** ответить на вопрос «Хватит ли времени ответить на сообщения?»

Это самостоятельный клиентский сайт без внешних зависимостей. Откройте `index.html` в современном браузере; сервер приложения, подписка, API и установка пакетов не требуются. Для публикации разместите `index.html`, `reply-capacity-core.js`, `reply-capacity-i18n.js` и `reply-capacity-ui.js` в одной папке статического хостинга.

## Что умеет

- Четыре параметра: новые сообщения за день, текущая очередь, средняя длительность одного ответа, доступные минуты ежедневно.
- Отображает, сколько ответов можно сделать в день, сколько накопится за 7 дней и насколько вырастет или уменьшится очередь.
- Вычисляет минимальный **дополнительный ежедневный бюджет времени**, чтобы за 7 дней разобрать и старую очередь, и все новые сообщения.
- Показывает график остатков очереди по каждому дню. Можно скопировать сценарий текстом.
- Значения сохраняются только в `localStorage` браузера, не отправляются на сервер. Кнопка «Сбросить пример» очищает сохранённые значения.
- Адаптирован для телефона и компьютера; без авторизации, без сетевых запросов и сторонней аналитики.
- Переключатель `EN | RU | FR | DE` переводит интерфейс, график, ARIA-подписи и копируемый результат без перезагрузки и изменения расчётов.

## Языки и хранение

При первом посещении всегда используется английский, независимо от языка браузера. Выбор языка хранится отдельно в `reply-capacity-language`; поддерживаются только `en`, `ru`, `fr`, `de`. Отсутствующее или некорректное значение означает английский. Введённые параметры по-прежнему хранятся в `reply-capacity-v1`. Сброс восстанавливает числовой пример, но сохраняет язык. При запрете localStorage приложение работает без сохранения между посещениями.

Словари всех четырёх языков находятся в `reply-capacity-i18n.js`, взаимодействие с DOM — в `reply-capacity-ui.js`. Используются встроенные `Intl.NumberFormat` и `Intl.PluralRules`. Вычислительное ядро не зависит от локализации. Новые строки следует добавлять под одинаковым ключом во все словари.

## Формула

`capacity_per_day = floor(available_minutes_per_day / minutes_per_reply)`

`queue_next = max(0, queue_previous + new_messages_per_day - min(capacity_per_day, queue_previous + new_messages_per_day))`

`required_capacity = new_messages_per_day + ceil(initial_queue / 7)`

`required_minutes_per_day = required_capacity * minutes_per_reply`

`extra_minutes_per_day = max(0, required_minutes_per_day - available_minutes_per_day)`

Это намеренно простая детерминированная модель. Новые сообщения считаются поступившими к началу каждого дня; 7 дней подряд имеют одинаковую нагрузку и одинаковый ресурс времени. Она не учитывает выходные, неравномерный поток сообщений, разную сложность обращений, пропущенные ответы, спам и автоматизацию. Не даёт обещаний относительно реальных будущих входящих.

## Связь с презентацией ДИН-Прогноз

Используем **только принципы, явно описанные на слайдах**: накопители (интегральные операторы), арифметика, ограничение ресурсов и управление их распределением, переключение состояния, сценарный пересчёт и контроль остатка. Самостоятельно реализованы операторы `STOCK`, `LIMIT`, `COMPARE` и `SWITCH` как элементарные вычисления. **Оригинальные математические уравнения, исходный код или SDK ДИН-Прогноз не получены и здесь не воспроизводятся.**

## Проверка

Node.js (только для тестирования, не для работы сайта):

```bash
node test-core.js
node test-ui.js
```

19 тестов ядра проверяют расчет очереди, крайние случаи, целочисленную пропускную способность, сохранение потока, детерминированность и правильность времени, необходимого для разгрузки. Один из тестов независимо проверяет баланс очереди и минимальность требуемого ежедневного бюджета на 3 360 сочетаниях параметров.

`test-ui.js` выполняет браузерные скрипты в Node.js VM с имитацией DOM: проверяет ввод, синхронизацию полей, сохранение, сброс, недоступный localStorage, копирование, предупреждение о нагрузке свыше 24 часов, полноту словарей, параметры строк, множественные числа, EN по умолчанию, сохранение языка, ARIA и неизменность расчётов при переключении. Это проверка логики, а не замена визуальной проверки.

`tests/browser.html` — отдельная страница технических проверок. Запустите `python -m http.server 8000` в корне проекта и откройте `http://localhost:8000/tests/browser.html`. Она проверяет реальный DOM на ширинах 320, 375, 390, 768 и 1280 px, во всех четырёх языках и трёх сценариях (обычный, максимальная нагрузка, пустая очередь): всего 60 сочетаний. Проверяются горизонтальное переполнение, расположение основных элементов внутри экрана, восстановление языка/данных при перезагрузке и нативная синхронизация поля/ползунка. Предыдущее содержимое двух ключей localStorage восстанавливается после проверки. Ручная оценка дизайна и работа скринридера остаются отдельными проверками.

GitHub Actions запускает оба набора Node.js и эту страницу в Chrome, доступном в среде runner. Дополнительно `tests/prepare-file-smoke.js` создаёт временную копию приложения для проверки реального запуска через `file://`. Проверяется старт, английский по умолчанию, смена языка без изменения расчётов и сброс с сохранением языка. В само приложение тестовые зависимости не добавляются.

Если для разгрузки требуется больше 1 440 минут в сутки, интерфейс поясняет, что сценарий для одного человека невозможен. Расчётная потребность во времени сохраняется без искусственного ограничения; она не означает, что такой бюджет физически доступен.

Результаты технического аудита и ограничения проверки приведены в [AUDIT.md](AUDIT.md).

## Что не входит в MVP

Нет сбора сообщений соцсетей, платёжной системы, CRM, прогнозирования конверсий, AI, автоматических ответов и сервера. Это намеренно однофункциональный MVP для проверки спроса.

## GitHub Pages: публикация

1. Создайте **публичный** репозиторий `reply-capacity` на GitHub.
2. Положите содержимое этой папки в **корень** репозитория (`index.html` должен лежать по пути `index.html`, а не `reply-capacity/index.html`).
3. После проверки Pull Request и явного разрешения владельца на слияние и публикацию откройте **Settings → Pages → Build and deployment → Deploy from a branch**, выберите `main` и `/(root)`, нажмите **Save**. Текущая подготовка PR сама по себе не публикует сайт.
4. После успешной публикации адрес будет `https://<GITHUB_USERNAME>.github.io/reply-capacity/`.
5. Проверьте **Actions → Reply Capacity tests**. Тесты автоматически запускаются при каждом push и pull request.

### Работа с Codex

Откройте Codex, подключите GitHub и выберите репозиторий `reply-capacity`. Прежде чем изменять код, попросите Codex запустить `node test-core.js`, проверить поведение и подготовить список ошибок. Инструкции по ограничениям проекта для Codex записаны в `AGENTS.md`.
