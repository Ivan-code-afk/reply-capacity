# Reply Capacity — рабочий MVP одной функции

**Задача:** ответить на вопрос «Хватит ли времени ответить на сообщения?»

Это готовый самостоятельный клиентский сайт без внешних зависимостей. Откройте `index.html` в любом современном браузере; сервер, подписка, API и установка пакетов не требуются. Для публикации можно разместить файлы `index.html` и `reply-capacity-core.js` на любом статическом хостинге.

## Что умеет

- Четыре параметра: новые сообщения за день, текущая очередь, средняя длительность одного ответа, доступные минуты ежедневно.
- Отображает, сколько ответов можно сделать в день, сколько накопится за 7 дней и насколько вырастет или уменьшится очередь.
- Вычисляет минимальный **дополнительный ежедневный бюджет времени**, чтобы за 7 дней разобрать и старую очередь, и все новые сообщения.
- Показывает график остатков очереди по каждому дню. Можно скопировать сценарий текстом.
- Значения сохраняются только в `localStorage` браузера, не отправляются на сервер. Кнопка «Сбросить пример» очищает сохранённые значения.
- Адаптирован для телефона и компьютера; без авторизации, без сетевых запросов и сторонней аналитики.

## Формула

`capacity_per_day = floor(available_minutes_per_day / minutes_per_reply)`

`queue_next = max(0, queue_previous + new_messages_per_day - min(capacity_per_day, queue_previous + new_messages_per_day))`

`required_capacity = new_messages_per_day + ceil(initial_queue / 7)`

`required_minutes_per_day = required_capacity * minutes_per_reply`

`extra_minutes_per_day = max(0, required_minutes_per_day - available_minutes_per_day)`

Это намеренно простая детерминированная модель. Новые сообщения считаются поступившими к началу каждого дня; 7 дней подряд имеют одинаковую нагрузку и одинаковый ресурс времени. Она не учитывает выходные, неравномерный поток сообщений, разную сложность обращений, пропущенные ответы, спам и автоматизацию. Не даёт обещаний относительно реальных будущих входящих.

## Связь с презентацией ДИН-Прогноз

Используем **только принципы, явно описанные на слайдах**: накопители (интегральные операторы), арифметика, ограничение ресурсов и управление их распределением, переключение состояния, сценарный пересчёт и контроль остатка. Самостоятельно реализованы операторы `STOCK`, `LIMIT`, `COMPARE` и `SWITCH` как элементарные вычисления. **Оригинальные математические уравнения, исходный код или SDK ДИН-Прогноз не получены и здесь не воспроизводятся.**

## Проверка

Node.js (только для тестирования, не для работы сайта):

```bash
node test-core.js
```

17 тестов проверяют расчет очереди, крайние случаи, целочисленную пропускную способность, сохранение потока, детерминированность и правильность времени, необходимого для разгрузки.

## Что не входит в MVP

Нет сбора сообщений соцсетей, платёжной системы, CRM, прогнозирования конверсий, AI, автоматических ответов и сервера. Это намеренно однофункциональный MVP для проверки спроса.

## GitHub Pages: публикация

1. Создайте **публичный** репозиторий `reply-capacity` на GitHub.
2. Положите содержимое этой папки в **корень** репозитория (`index.html` должен лежать по пути `index.html`, а не `reply-capacity/index.html`).
3. Откройте **Settings → Pages → Build and deployment → Deploy from a branch**, выберите `main` и `/(root)`, нажмите **Save**.
4. После успешной публикации адрес будет `https://<GITHUB_USERNAME>.github.io/reply-capacity/`.
5. Проверьте **Actions → Reply Capacity tests**. Тесты автоматически запускаются при каждом push и pull request.
